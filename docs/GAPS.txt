3. AI ANALYST GAPS — new, and only visible now that the transport is real
--------------------------------------------------------------------------------

The agent is built, bounded and measured, but has spoken to NOTHING but a local
test stand-in. Current: runner 2.0.0, prompts 2.0.0, catalogue 1.0.0,
boundary 1.0.0, llm_enabled=false, no API key configured.

3.1  NO REAL MODEL HAS EVER ANSWERED. Every proposal in the system came from a
     deterministic stand-in that echoes its payload. Behaviour against a real
     provider — refusals, drift, malformed output under load, latency — is
     UNMEASURED. The harness to measure it exists (`make agent-eval`) and is
     proven to detect a bad model (`make prove-agent-eval`); it has simply
     never been pointed at a real one.
     Closed by: an API key and the §3.2 decision.

3.2  DECISION OUTSTANDING: reaching a real provider requires adding
     `api.anthropic.com:443` to EGRESS_ALLOWLIST. That is a change to a
     SECURITY BOUNDARY. The probes are already written to survive it (NET-K2
     compares the allowlist against the CONFIGURED destination, not against a
     hardcoded stand-in; NET-K5 catches a mismatch; NET-K2:posture records
     which posture is in force), so the change does not weaken them — but it is
     yours to make, not mine.

3.3  (CLOSED) Conversational Q&A exists: seven READ-ONLY retrieval tools, a
     bounded multi-turn loop, a chat screen, and citation enforcement — an
     answer citing a handle it was never given is flagged. Every tool reads;
     there is no tool that starts, stops or changes an assessment, so "could
     the assistant act?" has a structural answer rather than a policy one.

3.4  (CLOSED) Cost controls: a per-run budget (60k tokens), a per-conversation
     budget (120k) and a deployment-wide daily cap (2M). Exhaustion is a
     RECORDED refusal, not a surprise. These are cost controls, not safety
     controls, and are labelled that way.

3.5  GROUNDEDNESS IS MEASURED CRUDELY. `agent_eval.py` catches invented paths,
     headers and parameters — the hallucination that matters most in a report —
     by lexical comparison against the evidence. It says nothing about whether
     the reasoning is good, and the tool labels itself that way everywhere.

3.6  NO COMPARISON AGAINST ANALYST-REVIEWED GROUND TRUTH. Explanations have
     never been scored against what a human analyst would have written.

4. CAPABILITY GAPS — code that does not exist yet
--------------------------------------------------------------------------------

4.1  (CLOSED) Retention, purge and invariant I12 are implemented: reference-
     aware, idempotent, and halting — every candidate is verified before any is
     deleted, so an inconsistency deletes nothing. Off by default
     (RETENTION_ENABLED=false); the API endpoint is dry-run unless asked.
     Remaining: it has never run against genuinely aged data. The window is 90
     days and nothing in the store is that old; every recorded run is a dry run
     that found 0 eligible blobs, which is the honest answer.

4.2  (CLOSED) API rate limiting exists: per-principal, reads and writes
     separated, health exempt, with an in-process fallback so a Redis outage
     never means NO limit. It protects availability, not a boundary, and is not
     a defence against a distributed flood.

4.3  (CLOSED) Evidence IS encrypted at rest: AES-256-GCM, key from the
     environment and never stored in the database, so a database dump cannot
     read evidence. Content addressing is unchanged (the digest is of the
     plaintext), each file says whether it is encrypted, and a store part-way
     through migration stays readable — currently 12 encrypted and 235
     plaintext blobs, all verified readable by `make evidence-rekey-check`.
     A wrong key or an altered file fails loudly rather than returning
     plausible bytes. OFF by default: an operator who loses the key has lost
     their evidence, so enabling it is a deliberate decision.
     Remaining: no re-key/rotation path — changing keys today means the old
     blobs become unreadable, so rotation needs a decrypt-and-rewrite pass.

4.4  Dual control cannot be satisfied with one operator. Two accounts held by
     one person are not independent approval, and the platform says so rather
     than simulating it. Every intrusive profile is therefore unreachable.

4.5  (CLOSED for the MVP) TWO assets are registered, each with its OWN
     unsigned authorisation document — signing one grants nothing for the
     other. An asset switcher drives every screen from one shared selection,
     and findings, coverage and conversations are scoped per asset.
     Remaining: no cross-asset roll-up view, and no bulk operations.

4.6  ONE SCANNER. Nuclei, authenticated scanning, EPSS/KEV enrichment, a
     platform priority score, multi-agent orchestration, a vector DB and
     Kubernetes remain deliberately deferred.

4.7  AUTHENTICATION is still a bearer token pasted into a form, issued out of
     band by `make db-seed`. Sign-out now exists and clears both the token and
     the remembered application, so a second analyst in the same tab inherits
     neither. Still missing: a login flow, session renewal, token rotation in
     the UI, and logout-everywhere.

4.8  NO TLS anywhere in the application plane. The dashboard is reached over
     plain HTTP on a loopback-only forwarder, not a published port. (The agent's
     outbound path does use TLS inside the CONNECT tunnel.)

4.9  REPORT REGENERATION is deterministic over identical inputs only. There is
     no report versioning and no diff between two reports.

6. ENVIRONMENT GAPS — true of this machine, not of the design
--------------------------------------------------------------------------------

6.1  (DECIDED, ADR-0015) Gate 2 now requires containment AND host hygiene, kept
     as separate verdicts. On this machine host hygiene FAILS: an unrelated
     project (`corelayer-lab-db`) publishes 0.0.0.0:5433.
     Measured: the lab cannot presently REACH it (TIMEOUT), while the host
     gateway is reachable at L3 (ECONNREFUSED on :22). The verdict was NOT
     changed on that basis — the drop is not a control this project owns.
     Recorded as probes PUB-2R:<port> which move no verdict.
     Closed by: its owner binding it to loopback. Another project's service was
     not removed, stopped or modified, and no host firewall rule was added.

6.2  `internal: true` is NOT host isolation (deviation D20). The host can reach
     container addresses directly. Containment means container->internet and
     container->LAN are blocked, verified by 118 probes plus an induced-failure
     proof.

6.3  Docker silently ignores `ports:` on a container attached only to internal
     networks (deviation D19). Nothing is published; the loopback forwarders
     are the deliberate alternative.

6.4  PDF rendering depends on native libraries baked into the api image
     (WeasyPrint + pydyf, both pinned after an unpinned pydyf broke it
     silently). Where absent, the artifact is recorded unavailable with its
     reason rather than failing the report.

7. WHAT IS NOT A GAP
--------------------------------------------------------------------------------
Listed because they are easy to mistake for one:

  - Gate 5 denying every live assessment. That is the authorisation control
    working, and it now also verifies the document has not changed since it was
    approved.
  - Gate 2 denying on host hygiene. That is the ADR-0015 decision working.
  - Categories showing zero findings with `detects`. The rule pack works; the
    fixtures contain no such detection.
  - `candidate` findings never confirmed. An unmapped scanner rule is kept and
    surfaced rather than dropped or guessed at.
  - `inconclusive` findings under partial coverage. Negative evidence is
    suppressed when collection was truncated; that is the soundness property.
  - The agent refusing to send a payload, or rejecting its own model's output.
    Both are the boundary working, and rejections are stored deliberately.
  - 50 generated reports and 99 fixture assessments in the database. That is
    accumulated development history, not production data.
