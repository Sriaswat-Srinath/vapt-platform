HOW TO READ THIS
  Gaps are grouped by the kind of thing that closes them: a human action, a
  configuration decision, missing code, or something deliberately out of scope.
  A gap is not a defect. Several of these are the system working as designed —
  they are listed because a reader of a report must know they exist.


--------------------------------------------------------------------------------
1. THE BLOCKING GAP — nothing has ever been scanned
--------------------------------------------------------------------------------

1.1  No live scan has ever run. Every finding, figure, report and coverage
     number in the platform derives from hand-authored, ZAP-shaped fixtures
     replayed in fixture mode. Real alert volumes, field shapes and
     false-positive rates will differ.
     Closed by: a human signing lab/authorisation/MOCK-WEB-001.md, then
     enabling scanner execution.

1.2  lab/authorisation/MOCK-WEB-001.md is an UNSIGNED DRAFT and is byte-
     identical to its first commit (83497ce). Gate 5 therefore denies every
     live assessment. This is the designed blocker, not a defect.
     Closed by: a human. The platform must not and cannot sign it.

1.3  Standing safety posture, all false and all deliberate:
       scanner_execution_enabled = false
       zap_adapter_enabled       = false
       active_scan_enabled       = false
       dual_control_available    = false  (effective: false)
       llm_enabled               = false
     Each is a separate, auditable decision. Enabling one does not enable
     another.

2.1  Five Tier-1 categories are SURFACE ONLY. The platform identifies where
     they would apply and can say nothing about whether they are present.
     Blocked by: active scanning disabled AND dual control unavailable.
     These need crafted requests, which is intrusive by definition.
       - broken access control (IDOR, privileged paths)
       - authentication (enumeration, recovery flows)
       - file upload (type/size/storage enforcement)
       - API security (object-level authorisation, mass assignment)
       - SSRF (caller-controlled fetch destinations)

2.2  Injection is PARTIAL. Reflected XSS and SQLi are catalogued and the
     reflected-input rule can confirm an unencoded reflection in HTML context.
     Confirming that an interpreter was reached needs payloads. A clean
     injection result here is not a clean injection result.

2.3  Business logic has NO CAPABILITY and never will have an automated one.
     No scanner confirms a logic flaw. The matrix flags the surface (price,
     quantity, coupon-shaped parameters) for a human and stops there.

2.4  Cryptographic failures and client-side show 0 findings despite 3 and 2
     catalogue entries and a working rule pack. The fixtures simply do not
     contain those detections yet. This is a FIXTURE gap, not a code gap.

2.5  One finding carries no taxonomy category (an unmapped scanner rule). It
     is counted and surfaced separately rather than hidden.

2.6  All of Tier 2 is catalogued-as-a-name only, by your sequencing. Denial of

3. CAPABILITY GAPS — code that does not exist yet
--------------------------------------------------------------------------------

3.1  Invariant I12 (purge is idempotent and halts on inconsistency) is the only
     invariant still unimplemented. Due at phase 8.

3.2  Retention and purge are NOT implemented. The reference-aware deletion
     guard exists and is tested (I7), but there is no scheduled purge run, no
     RETENTION_ENABLED setting in config, and no halt-on-inconsistency
     behaviour. Evidence accumulates indefinitely.

3.3  No rate limiting on the API. Scanner request budgets exist and are
     enforced per job (requests/sec, total requests, duration); the HTTP API
     itself has none.

3.4  Evidence is not encrypted at rest. Host full-disk encryption is assumed
     and is NOT verified by the platform (assumption B7).

3.5  Dual control cannot be satisfied in a single-operator environment. Two
     accounts held by one person are not independent approval, and the
     platform says so rather than simulating it. Every intrusive profile is
     therefore unreachable.

3.6  One asset only. Every screen operates on the first registered asset;
     there is no asset switcher, and multi-asset coverage roll-up does not
     exist.

3.7  One scanner. Nuclei, authenticated scanning, EPSS/KEV enrichment, a
     platform priority score, multi-agent orchestration, a vector DB and
     Kubernetes were all deliberately deferred in the MVP re-scope.

3.8  Authentication is a bearer token pasted into a form. No login flow, no
     session renewal, no logout-everywhere, no token rotation UI. Tokens are
     issued out of band by `make db-seed`.

3.9  The dashboard is reached through an opt-in loopback forwarder, not a
     published port, and is served over plain HTTP on 127.0.0.1. There is no
     TLS anywhere in the application plane.

3.10 The agent is a bounded single pass, not a LangGraph graph. It has no
     executable tools, so iteration buys nothing a second analyst request
     would not. Revisit if tools that read more data are ever added.


--------------------------------------------------------------------------------
4. ASSURANCE GAPS — what is not being checked
--------------------------------------------------------------------------------

4.1  No CI pipeline. There is no .github/workflows; every suite is run by hand.
     The invariant manifest test exists to catch a skipped safety test, but
     nothing runs it automatically on a change.

4.2  No lint or type-check configuration. No ruff.toml, pyproject.toml or
     mypy.ini. The frontend is type-checked only as part of its Docker build
     (`npx tsc --noEmit`).

4.3  No frontend tests at all. The dashboard is verified by running it and
     looking, plus the backend's HTTP-level assertions about headers, the
     auth-through-proxy behaviour and the bundle contents.

4.4  The LLM stand-in is not a model. It returns deterministic canned
     proposals shaped like model output. Behaviour against a real provider —
     refusals, drift, malformed JSON under load, latency — is unmeasured. The
     parser treats all model output as untrusted input, which is the mitigation.

4.5  The reflected-unencoded heuristic is exercised by two fixtures. A real
     XSS corpus would test it far harder.

4.6  Rule coverage is five evidence classes (missing_header, header_value,
     pattern_in_body, reflected_input, cookie_attribute). Anything else stays
     `candidate` with the gap recorded, which reads as under-reporting and is
     the intended direction of error.

4.7  Report regeneration is deterministic over identical inputs only. New
     assessments change the content by design; there is no report versioning
     or diff between two reports.

5.2  `internal: true` is NOT host isolation. The host can reach container
     addresses directly (measured deviation D20). Containment means container
     -> internet and container -> LAN are blocked, which is verified by 115
     probes plus an induced-failure proof.

5.3  Docker silently ignores `ports:` on a container attached only to internal
     networks (measured deviation D19). Nothing is published; the forwarders
     are the deliberate alternative.

5.4  PDF rendering depends on native libraries baked into the api image
     (WeasyPrint + pydyf, both pinned after an unpinned pydyf broke it
     silently). Where they are absent the artifact is recorded unavailable
     with its reason rather than failing the report.


--------------------------------------------------------------------------------
6. WHAT IS NOT A GAP
--------------------------------------------------------------------------------

Listed because they are easy to mistake for one:

  - Gate 5 denying every live assessment. That is the authorisation control
    working.
  - Categories showing zero findings with `detects`. The rule pack works; the
    fixtures contain no such detection.
  - `candidate` findings that were never confirmed. An unmapped scanner rule
    is kept and surfaced rather than dropped.
  - `inconclusive` findings under partial coverage. Negative evidence is
    suppressed when collection was truncated; that is the soundness property.
  - The agent refusing to send a payload. A refusal is the boundary working.
