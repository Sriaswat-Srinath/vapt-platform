# MVP Phase 2 — Backend core

Baseline `4886f44`. **Real application code now exists**: FastAPI, PostgreSQL schema, auth,
assets, scope, the full preflight gate chain and the audit chain. No scanner execution, no
discovery, no agent, no reports yet. Flags `false`; authorisation document untouched and unsigned.

## 1. What was built

| Area | Delivered |
|---|---|
| Service | FastAPI on `vapt-api:dev` (Debian-slim base **digest-pinned**), non-root `65532`, read-only rootfs, `cap_drop ALL`, bound to the **`vapt_edge` interface only** |
| Schema | 13 tables via Alembic (`40d82117bfaf`, `b2000000add`, `b3000000seq`): analysts, api_tokens, operator_identities, audit_log, assets, scope_rules, scope_grants, approvals, lab_isolation_checks, scope_decisions, scan_profiles, scan_jobs, scan_job_events |
| Auth | opaque tokens `vapt_<id>_<secret>`, **Argon2** hashed, expiry + revocation + `last_used_at`; roles analyst / approver / admin |
| Assets | register, list, get, patch (identity fields absent by design), archive |
| Scope | scope rules (include/exclude, method allowlists), **grants with the signed-document CHECK**, approvals, operator identities with no self-attestation |
| Gate chain | all **13 gates** in `app/safety/scope_policy.py` — pure, total, ordered, versioned (`1.0.0`) |
| Jobs | assessment creation **only** on an allow decision; job events; per-job scope decision retrievable |
| Audit | append-only hash chain + `/audit/verify` |
| System | health, readiness (db/redis/isolation), capabilities, isolation ingest |

The safety layer imports nothing but the standard library: no I/O, no ORM, no LLM. `evaluate()` is a
pure function of an immutable snapshot, and any exception inside a gate becomes a **deny**.

## 3. Defects found and fixed

| Defect | Fix |
|---|---|
| `audit_log.seq` used `autoincrement` on a non-PK column, so Alembic emitted a plain `INTEGER NOT NULL` and every insert failed | migration `b3000000seq` converts it to a real `BIGINT … GENERATED BY DEFAULT AS IDENTITY`; the chain order comes from the database |
| The API's **own healthcheck** got HTTP 403 — `HTTP_PROXY` was set, so urllib routed an internal request through the egress proxy, which correctly refused it | `NO_PROXY` for internal hosts + a healthcheck using `http.client` (no proxy handling). This was the proxy working as designed |
| Asset registration required resolving the hostname, which the API **cannot** do (no `vapt_lab` route, by design) | registration validates form + rejects decisively if resolution *succeeds* outside the lab subnet; authoritative resolve-once-and-pin is the worker's job at gate 8, and gate 8 says so rather than implying validation happened |
| The dry run short-circuited, so a stakeholder saw one gate | `evaluate(short_circuit=False)` for dry runs only; the authoritative path still short-circuits, and the decision is identical |
| Unevaluated gates reported internal symbols (`g6`, `g7`) | gates carry stable names |
| `NET-B:api` demanded a registry digest for a locally built image | first-party images must have a **digest-pinned `FROM`** and a running image id matching the build; third-party images still require a registry digest |

## 4. Limitations

1. **No scanner execution.** `SCANNER_EXECUTION_ENABLED=false`; no worker, no adapter, no ZAP call.
2. **Gate 8 cannot pass from the API.** Resolution belongs to the worker (phase 3). Until then every
   assessment is denied at gate 8 even if gates 1 and 5 were satisfied — deliberately honest.
3. **No scope grant can be activated** because `lab/authorisation/MOCK-WEB-001.md` is unsigned.
   This is the designed blocker, and it is the one action only a human can take (see §5).
4. `frontend` and `worker` are still placeholders. No dashboard yet (phase 6).
5. Document hash re-verification at gate 5 currently checks the recorded `document_state`; comparing
   the live file hash on every evaluation needs the operator-reported hash flow (phase 3).
6. Dev seed issues tokens into the git-ignored `.lab-state/tokens.json`. Not a production auth story.
